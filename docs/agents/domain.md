# Domain Docs

This repo uses a single-context layout.

## Before exploring

- Read `GLOSSARY.md` at the repository root.
- Read ADRs in `docs/adr/` that concern the area being explored.

If these files are absent, proceed silently. The `/domain-modeling` skill,
also reached through `/grill-with-docs` and `/improve-codebase-architecture`,
creates them when terms or decisions are resolved.

## Vocabulary

Use the glossary's terms when naming domain concepts in issues, proposals,
hypotheses, and tests. Follow its distinctions and avoided synonyms.

If a concept is missing, reconsider whether it belongs to the domain.
Record a real vocabulary gap for `/domain-modeling`.

## Decision conflicts

If a proposal contradicts an existing ADR, identify the ADR explicitly
and explain why the decision merits reopening.
